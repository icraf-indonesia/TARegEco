Overview

The Regional Economic Projection module in LUMENS projects a region’s economic trajectory under alternative future scenarios. Building on the Regional Economic Descriptive Analysis, this module couples a supply-constrained mixed Input-Output (IO) model with land-use projections to answer questions like:

  • How will regional GDP, employment, and household income evolve through 2049?
  • What happens if land use changes (Asumsi 1), productivity rises (Asumsi 2), or downstream industries expand (Asumsi 3)?
  • Which sectors gain or lose economic weight under each intervention?

The module produces comparable projections across the Business-As-Usual (BAU) baseline and one or more intervention assumptions, giving stakeholders a quantitative basis for policy design that balances economic growth with sustainable land use.

Key Concepts

  1. Business-As-Usual (BAU): The reference scenario. It uses the baseline land-use projections and historical growth rates without any policy intervention. Every projection result is compared against BAU.

  2. Asumsi 1 — Land Use Change: Simulates the impact of changing land area (via luc_projection) or land proportion/distribution (via land_proportion). Output of land-constrained sectors is recalculated as area × Land Productivity Coefficient (LPC).

  3. Asumsi 2 — Productivity Improvement: Simulates an increase in Land Productivity Coefficient (LPC) over time. The LPC rises incrementally from baseline toward a user-defined target, boosting output per hectare without expanding the land footprint.

  4. Asumsi 3 — Downstreaming (Hilirisasi): Simulates structural change in the IO table. A portion of a raw commodity’s output is redirected into a downstream processing sector; the modified transaction matrix (ΔZ) and output targets (ΔX) are rebalanced using the RAS algorithm to produce a consistent, balanced IO system.

  5. Supply-Constrained Mixed IO Model: A hybrid Leontief model. Land-constrained sectors (co) are bounded by land availability × LPC; non-land sectors (nc) are solved via the Leontief inverse. This lets the model respect land-use limits while still accounting for inter-sectoral demand.

  6. Linkage Indices (ITBL & ITFL):

    • ITBL (Indeks Total Backward Linkage) — how strongly a sector pulls demand from upstream sectors.
    • ITFL (Indeks Total Forward Linkage) — how strongly a sector supplies inputs to downstream sectors.

    Comparing ITBL/ITFL before and after a scenario reveals which sectors gain or lose strategic importance.

  7. RAS Balancing (Biproportional Matrix Balancing): An iterative scaling algorithm (Miller & Blair, 2009) that adjusts the IO coefficient matrix A until row and column margins match new targets. Used to keep the IO table consistent after Asumsi 3 interventions.

Data and Input Variables

Before running the projection, prepare the following:

  1. Baseline (descriptive analysis output) — either:

    • Descriptive_Analysis_Module.rds — the RDS file generated by the Descriptive Analysis module (recommended), or
    • IO_Analysis_Output.xlsx — the Excel workbook with all baseline sheets (GDP, Leontief_Matrix, Full_IO_Table, Land_Proportion, Multiplier_*, Linkage, Code_Registry, etc.).

  2. BAU Land Projection (luc_projection.xlsx) — the projected land area for each land-cover class, with columns ID, LC, and one column per projection year.

  3. Asumsi 1 inputs (optional) — Excel file with:

    • luc_projection sheet (required): same schema as the BAU land projection.
    • land_proportion sheet (optional): sector × land-cover proportions.

  4. Asumsi 2 input (optional) — produktivitas_lpc.xlsx generated from the template. Contains sector list, baseline LPC, and target growth factors or target LPC values.

  5. Asumsi 3 input (optional) — perubahan_io.xlsx generated from the template. Contains ΔZ (transaction changes between sectors) and ΔX (output changes for source and destination sectors).

Tip: Use the download template buttons on each assumption tab (A1, A2, A3) to generate pre-filled Excel files with the correct sector list, LC names, and column structure. Do not rename columns in the template — the loader expects exact headers.

Accessing Outputs

After the analysis completes, the following files are written to your chosen output directory:

  1. Projection HTML Report (Projection_Report_<scenario>_<timestamp>.html) — an interactive report with:
    • Log of inputs (baseline file, BAU file, and per-assumption files).
    • Executive summary (initial vs final year values, growth rate) per indicator.
    • Per-indicator sections: PDRB, Serapan Tenaga Kerja, Pendapatan Tenaga Kerja, Surplus Usaha Bruto, Output — each with a recap table (BAU vs Scenario + % difference) and a plotly chart.
    • Sectoral analysis: Top-20 sectors by GDP, labour, and output.
    • Linkage changes (only if Asumsi 3 is active): ITBL and ITFL before vs after, top 10 movers.
  2. Projection Results Excel (Hasil_Proyeksi_<scenario>_<timestamp>.xlsx) — multi-sheet workbook containing:
    • Recap_Skenario — yearly recap for the scenario.
    • Recap_BAU — yearly recap for BAU.
    • Detail_Skenario — sector-level results for the scenario.
    • Detail_BAU — sector-level results for BAU.
    • Linkage — ITBL/ITFL before and after (if Asumsi 3 active).
    • Metadata — scenario name, active assumptions, period, sector count.

Interpreting the Results

  • Absolute values — projections are in the unit of the baseline (e.g., Rp Juta for GDP, Orang for labour). Units are shown in each table header.
  • % difference — the relative gap between scenario and BAU. Positive means the scenario produces more of that indicator than BAU; negative means less.
  • Linkage deltas (ΔITBL, ΔITFL) — a positive Δ means the sector becomes more strategically important after the intervention. A negative Δ means it weakens.
  • Trend direction — check whether gains/losses are consistent over the horizon or only appear late (compound effect). Early divergence suggests a strong, direct scenario effect; late divergence suggests compounding.
